# Every package the direct requirements pull in, pinned, so two builds of
# one commit install the same thing. Only requirements.txt was pinned, and
# everything beneath it - beets' tree, uvicorn's, pydantic - floated to
# whatever was newest on the day the image was built.
#
# Direct requirements are left out on purpose: they are pinned in
# requirements.txt, where Dependabot bumps them, and pinning them here too
# would make every bump a conflict.
#
# Regenerate after changing requirements.txt, for the image's platform:
#   uv pip compile requirements.txt --python-version 3.13 #     --python-platform aarch64-unknown-linux-gnu --no-header -o lock.txt
# then keep the lines for packages not named in requirements.txt.
# Except yt-dlp-ejs, which yt-dlp itself pins exactly: pinning it
# here too would fail every yt-dlp bump that moves it.
